A Card Sort question asks respondents to drag cards representing items, concepts, or content into categories. This is a foundational UX research method for understanding how people mentally organise information, which helps design navigation, menus, and information architecture.

## When to use this question type

- You are designing or restructuring a website or app menu and want to understand user mental models.
- You need to validate category labels and groupings with real users.
- You want to discover unexpected groupings that could improve findability.

## How to add it

<Steps>
  <Step>
    In the questionnaire builder, click **Add questions**.
  </Step>
  <Step>
    Select **Card Sort** from the popup.
  </Step>
  <Step>
    The question appears on the canvas. Click it to open the configuration panel and add cards, define categories, and choose the sort type.
  </Step>
</Steps>

## Settings

| Setting | Description |
| --- | --- |
| Cards | The items respondents will sort, for example, product names or page titles. |
| Categories | The groups respondents drag cards into. In an open sort, respondents create their own categories. |
| Sort type | **Closed**: respondents sort into pre-defined categories. **Open**: respondents create and name their own categories. **Hybrid**: pre-defined categories plus the option to add new ones. |
| Mandatory | Requires all cards to be sorted before the respondent can continue. |
| Randomise cards | Shuffles the order of cards for each respondent. |
| Allow multiple cards per category | Lets respondents place more than one card in the same category. |

<Note>
  **Needs product verification:** Confirm whether "Maximum categories" and "Time limit" settings exist for this question type.
</Note>

## What respondents see

Respondents see a set of cards on one side and category areas on the other. They drag each card into a category. In an open sort, they can also type a name for each new category they create. A counter may show how many cards remain unsorted. If mandatory, they must sort all cards before continuing.

<Warning>
  Card Sort questions involve drag-and-drop interaction and category validation. Always preview and test the full questionnaire before launching to ensure cards and categories behave correctly on different devices.
</Warning>

## Logic and piping

You can use the final category assignments in logic to show or hide later questions. For example, if a respondent places a specific card in a particular category, you can branch to a follow-up about that grouping. For full instructions, see [Logic and branching](/questionnaire/logic-and-branching).

## Results in reporting

Results appear as a matrix showing the percentage of respondents who placed each card in each category. In open sorts, a list of user-created category names is shown with frequency counts. A similarity matrix or dendrogram may be available to visualise grouping patterns.

## Example use case

A university is redesigning its website. It runs a closed card sort with 30 cards representing academic pages and 6 pre-defined categories: "Study", "Research", "About us", "Students", "Staff", and "News". The results show that respondents frequently place "Library" under "Study" rather than "Students", leading to a menu restructure.
